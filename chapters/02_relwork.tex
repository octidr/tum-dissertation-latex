\chapter{Background and Fundamentals}
\label{chap:background}

This chapter introduces the fundamental concepts required for
understanding the research presented in this dissertation.
First, the foundations of real-time systems and scheduling
theory are discussed, including timing constraints, scheduling
algorithms, and real-time operating systems. Afterwards, the
concept of mixed-criticality systems is introduced together
with the challenges associated with resource sharing and
adaptability in modern embedded platforms.
Subsequently, distributed real-time systems and modern
automotive computing architectures are analyzed, including
heterogeneous systems, edge computing, and task offloading
concepts. Finally, the chapter presents the networking
technologies and communication mechanisms commonly used in
distributed cyber-physical systems with real-time requirements.

\section{Real-Time Systems}
\label{sec:rtsystems}

Real-time systems are computing systems in which correctness
depends not only on the logical correctness of the produced
results, but also on the time at which these results are
generated~\cite{buttazzo2011}. In such systems, timing
constraints are treated as first-class requirements and must
be satisfied in order to guarantee correct system behavior.
Real-time systems are commonly classified into hard real-time,
firm real-time, and soft real-time systems depending on the
consequences of missing timing deadlines. In hard real-time
systems, missing a deadline may lead to catastrophic failures,
making deterministic timing guarantees essential. Firm
real-time systems occupy an intermediate position: a missed
deadline renders the result valueless, but unlike hard
real-time systems, individual misses do not necessarily
trigger a system failure. Soft real-time systems, on the other
hand, can tolerate occasional deadline misses with graceful
degradation of quality of service.

Each task in a real-time system is typically characterized by
a set of parameters: its release time (or arrival time), an
execution time, a relative deadline, and---for periodic
tasks---a period. The Worst-Case Execution Time~(WCET) is a
particularly critical parameter, as it represents an upper
bound on the time a task may require under any input and
execution condition. Deriving tight and safe WCET estimates
is a research challenge in its own right, with techniques
ranging from static analysis~\cite{wilhelm2008} to
measurement-based approaches~\cite{engblom2002}. The
inherent trade-off between safety (overestimation) and
efficiency (tight bounds) is especially pronounced in
heterogeneous and many-core platforms, where cache effects,
pipeline speculation, and memory contention increase
analysis complexity.

Modern cyber-physical systems such as automotive platforms,
industrial controllers, robotics systems, and autonomous
vehicles increasingly depend on strict timing guarantees while
simultaneously requiring higher computational flexibility and
adaptability~\cite{baunach2018,sdv2024}. This combination
introduces significant challenges for system design and
resource management.

\subsection{Scheduling Theory}
\label{subsec:scheduling}

Scheduling is one of the core concepts in real-time systems
and refers to the process of determining the execution order
of tasks while satisfying timing constraints and resource
limitations. Classical real-time scheduling approaches include
fixed-priority scheduling algorithms such as Rate Monotonic
(RM), as well as dynamic-priority approaches such as
Earliest-Deadline-First (EDF).

Liu and Layland~\cite{liu1973} introduced one of the
foundational scheduling models for periodic real-time tasks,
establishing schedulability bounds for rate-monotonic (RM) and earliest-deadline-first (EDF) scheduling.
EDF scheduling is particularly relevant due to its optimality
properties for uniprocessor systems under specific assumptions:
it is known to be optimal in the sense that if any algorithm
can schedule a task set on a single processor, EDF can also
schedule it. Fixed-priority schemes such as RM, while not
theoretically optimal, offer simpler analysis and more
predictable behavior in the presence of task interactions,
making them dominant in practice. A comparison between schedules generated with both RM and EDF policies is shown in Fig. \ref{fig:schedexample}, where we can notice that in many cases, the dynamic policy of EDF is able to find a schedule without missing deadlines, while RM misses deadlines for T2 in job 1.

Schedulability analysis is the formal process of determining
whether a task set will always meet its deadlines under a
given scheduling policy. Response Time Analysis~(RTA) for
fixed-priority systems~\cite{joseph1986} and utilization-based
bounds for EDF~\cite{liu1973} are well-established analytical
tools. However, extending such analyses to account for
blocking from shared resources, interrupt handling, and
inter-task communication requires additional models such as
the Sporadic Server or the Stack Resource Policy~\cite{baker1991}.

As modern embedded systems evolved towards multicore and
heterogeneous architectures, scheduling approaches also became
more complex. Multiprocessor scheduling introduces additional
challenges including task migration overhead, synchronization,
resource sharing, cache interference, and communication
latency~\cite{megel2010}. Broadly, multiprocessor scheduling
strategies are classified into partitioned, global, and
semi-partitioned (or clustered) approaches. Partitioned
scheduling assigns each task permanently to one processor and
applies uniprocessor analysis independently, at the cost of
possible inefficiency due to bin-packing constraints. Global
scheduling allows tasks to migrate freely across processors,
improving utilization but introducing runtime migration
overhead and making formal analysis significantly harder.
Semi-partitioned and cluster-based approaches attempt to
balance these trade-offs~\cite{davis2011}.

\subsection{Real-Time Operating Systems}
\label{subsec:rtos}

Real-Time Operating Systems (RTOSs) provide the software
infrastructure required for executing time-critical tasks
while maintaining deterministic system behavior. Compared to
general-purpose operating systems, RTOSs prioritize
predictability, bounded latency, and deterministic scheduling
behavior over throughput optimization.

Common RTOS functionalities include task scheduling,
inter-process communication, synchronization primitives,
interrupt handling, and memory management. Depending on the
system requirements, RTOSs may support static scheduling,
dynamic scheduling, partitioning, or mixed-criticality
execution models. Well-known examples include
OSEK/VDX~\cite{osek2005} and AUTOSAR Classic Platform, which
are widely deployed in automotive embedded systems, as well as
more general-purpose RTOSs such as FreeRTOS and VxWorks.

The AUTOSAR Adaptive Platform~\cite{autosar2023} represents a
more recent development targeted at high-performance
automotive computing nodes. Unlike the Classic Platform, which
is oriented towards microcontrollers with static task
configurations, the Adaptive Platform supports dynamic
application deployment, service-oriented communication, and
POSIX-compliant execution environments, all while maintaining
defined timing and isolation guarantees. This architectural
shift is particularly relevant for the integration of
mixed-criticality workloads and dynamic task management in
modern vehicle platforms.

In distributed and heterogeneous systems, RTOSs additionally
play an important role in enabling communication, coordination,
and resource sharing between different hardware nodes. The
ability to support runtime adaptation and dynamic task
migration increasingly represents an important requirement for
modern distributed embedded systems. Hypervisor-based
virtualization is increasingly used to consolidate multiple
RTOS instances or mixed-criticality partitions on a single
hardware platform~\cite{heiser2020}, providing spatial and
temporal isolation with lower hardware costs.

\section{Mixed-Criticality Systems}
\label{sec:mcs}

Mixed-criticality systems~(MCS) are systems in which
applications with different levels of criticality coexist on
shared hardware resources~\cite{vestal2007,burns2017}. Such
systems are especially relevant in domains including
automotive systems, avionics, robotics, and industrial
automation, where safety-critical and non-safety-critical
applications execute simultaneously within the same platform.

Traditionally, critical systems relied on strong spatial and
temporal partitioning mechanisms in order to isolate workloads
with different certification requirements. While this approach
improves safety and predictability, it may also lead to low
resource utilization and reduced flexibility.

Vestal~\cite{vestal2007} introduced one of the most influential
mixed-criticality models, where tasks are associated with
different Worst-Case Execution Time (WCET) estimations
depending on their assurance level. Specifically, a
high-criticality task carries a pessimistic (safe) WCET
estimate for use under high-assurance conditions, and a
more optimistic estimate for use when the system operates
in a nominal low-load mode. Since then, multiple scheduling
approaches have been proposed to support dynamic adaptation
and graceful degradation under overload conditions. The
mixed-criticality model of Baruah et al.~\cite{baruah2011}
extended Vestal's original formulation to a formal
schedulability framework under EDF, providing a foundation
for a significant body of subsequent research.

% ------------------------------------------------------------
\subsection{Criticality Levels and Standards}
\label{subsec:criticality_standards}

In safety-critical domains, criticality levels are often
defined by domain-specific standards. In avionics, the
DO-178C standard defines Design Assurance Levels (DALs)
A through E for software, where DAL~A represents the
highest assurance requirement for functions whose failure
could cause catastrophic consequences~\cite{do178c2011}. The
corresponding hardware standard DO-254 applies analogous
levels to electronic hardware design. In automotive systems,
ISO~26262 defines Automotive Safety Integrity Levels
(ASILs) ranging from ASIL~A to ASIL~D, with ASIL~D
representing the most stringent requirements for functions
whose failure could lead to severe injuries or
fatalities~\cite{iso26262_2018}. For general functional
safety across industrial domains, IEC~61508 defines Safety
Integrity Levels (SILs) 1 through 4.

These standards impose requirements not only on the software
algorithms themselves but also on the processes, tools,
verification methods, and evidence used during development.
When components of different criticality share hardware
resources, demonstrating compliance becomes significantly
more complex, as the behavior of lower-criticality components
may potentially interfere with higher-criticality ones.
Achieving compositionality, i.e. the ability to verify system
properties from verified component properties, is a central
challenge in the design of mixed-criticality platforms.

% ------------------------------------------------------------
\subsection{Scheduling and Resource Management for MCS}
\label{subsec:mcs_scheduling}

Modern mixed-criticality systems increasingly explore adaptive
resource management techniques in order to improve efficiency
while preserving timing guarantees~\cite{adaptive2023}.
In the standard mixed-criticality scheduling model, the
system can transition between a low-criticality (LO) mode
and a high-criticality (HI) mode. When the observed execution
time of a high-criticality task exceeds its LO-mode WCET
estimate, the system switches to HI mode, abandoning or
reducing the service of low-criticality tasks in order to
guarantee that all high-criticality deadlines are met.

Several extensions to this basic model have been proposed.
The AMC (Adaptive Mixed Criticality) scheduler~\cite{burns2013}
uses per-task mode switching rather than a global transition,
allowing finer-grained adaptation. Elastic scheduling
approaches attempt to dynamically adjust task parameters
(periods, execution budgets) in response to load changes
while maintaining feasibility constraints. Research on
\emph{service degradation} policies addresses the question of
how best to reduce the service of lower-criticality tasks
during overload, recognizing that an abrupt shutdown of
lower-criticality functions may itself introduce safety risks.

Recent research has also investigated stronger isolation
mechanisms and heterogeneous execution models for
mixed-criticality platforms~\cite{hoornaert2024,tinto2024}.
Cache coloring and cache partitioning have emerged as
important mechanisms for reducing cache interference between
tasks of different criticality levels executing on shared-cache
multicore platforms~\cite{mancuso2013}. Memory bandwidth
regulation and the use of memory protection units~(MPUs) or
memory management units~(MMUs) further contribute to
spatial isolation guarantees.

In distributed cyber-physical systems such as modern
automotive platforms, mixed-criticality introduces additional
complexity due to communication delays, distributed resource
sharing, synchronization constraints, and heterogeneous
hardware architectures. These systems must simultaneously
maintain timing guarantees, fault tolerance, and runtime
adaptability across multiple interconnected nodes. The
integration of mixed-criticality scheduling with distributed
resource management and task migration constitutes a central
open challenge addressed in this dissertation.

\section{Distributed Real-Time Systems}
\label{sec:distributed}

Distributed real-time systems consist of multiple computing
nodes that cooperate in order to execute time-critical tasks
while communicating over a network infrastructure. Such
systems are commonly used in domains including automotive
electronics, industrial automation, aerospace systems, and
large-scale cyber-physical systems. In contrast to
uniprocessor or shared-memory multiprocessor systems,
distributed systems must cope with the inherent uncertainty
of network communication, including variable transmission
delays, packet losses, and clock synchronization errors,
all while satisfying end-to-end timing constraints.

Modern automotive systems increasingly evolve from
domain-oriented architectures composed of numerous Electronic
Control Units~(ECUs) towards centralized and zonal
architectures based on high-performance computing
platforms~\cite{sdv2024,automotivehpc2023}. This transition
is motivated by the growing computational requirements of
software-defined functionalities, autonomous driving systems,
and advanced driver assistance systems~(ADAS). A zonal
architecture groups ECUs by physical location in the vehicle
rather than by function, with high-bandwidth Ethernet backbones
connecting zone controllers to central compute nodes. This
consolidation reduces wiring complexity and weight while
enabling more powerful centralized processing, but also
concentrates risk and demands stronger mechanisms for
isolation and fault containment.

Distributed architectures provide several advantages,
including scalability, fault tolerance, workload
distribution, and resource sharing. However, they also
introduce challenges associated with synchronization,
communication latency, scheduling coordination, and
distributed resource management.

% ------------------------------------------------------------
\subsection{End-to-End Timing Analysis}
\label{subsec:e2e}

A fundamental challenge in distributed real-time systems is
the analysis of end-to-end latency for processing chains
that span multiple nodes. A \emph{cause-effect chain} (or
task chain) is a sequence of tasks executing on potentially
different nodes, where each task consumes the output of the
previous one. The end-to-end latency of such a chain is
determined not only by the execution times of individual
tasks, but also by their activation patterns, scheduling
decisions on each node, and the communication delays
incurred at each link.

The problem of bounding end-to-end latency has been studied
through several analytical frameworks. The work of
Dürr et al.~\cite{durr2019} provides a systematic
characterization of end-to-end latency semantics,
distinguishing between \emph{reaction time} (the worst-case
delay from an external event to the completion of the last
task in the chain) and \emph{data age} (the maximum
staleness of data observed by the final consumer). These
two metrics capture different aspects of real-time
correctness relevant to different application domains;
for example, control systems are typically more sensitive to
data age, whereas event-triggered safety responses demand
short reaction times.

% ------------------------------------------------------------
\subsection{Heterogeneous and Edge Computing Platforms}
\label{subsec:hetero_edge}

Modern distributed embedded systems frequently combine
heterogeneous computing resources including CPUs, GPUs,
FPGAs, and specialized accelerators. Such heterogeneous
platforms can improve performance and energy efficiency but
also increase system complexity and scheduling challenges.
The diversity of instruction set architectures, memory
hierarchies, and programming models across these processing
elements means that tasks cannot in general be freely
migrated without adaptation of the application binary or
execution environment.

The emergence of edge and Multi-access Edge Computing~(MEC)
architectures additionally enables the distribution of tasks
between embedded devices, edge servers, and cloud
infrastructure~\cite{mec2017}. This paradigm supports
workload offloading, adaptive deployment, and resource
elasticity while reducing latency compared to centralized
cloud computing approaches. In latency-sensitive
cyber-physical applications, edge computing plays a
particularly important role by enabling local processing
of sensor data with sub-millisecond response times that
would be infeasible with round-trips to a remote cloud.

Task offloading and workload distribution mechanisms are
closely related to orchestration concepts commonly used in
cloud and Internet-of-Things (IoT) environments. In such
systems, orchestration mechanisms coordinate deployment,
resource allocation, monitoring, and execution management
across multiple distributed nodes. Container-based
virtualization and lightweight orchestration frameworks,
originally developed for cloud-native applications, are
increasingly being adapted for edge and embedded
contexts~\cite{morabito2018}, though the real-time and
safety guarantees required in cyber-physical systems
impose constraints that are not natively addressed by
mainstream cloud orchestration tools.

% ------------------------------------------------------------
\subsection{Task Migration and Runtime Adaptation}
\label{subsec:taskmig}

Task migration refers to the process of transferring a task
or workload from one execution node to another during system
operation. Migration mechanisms may be used for fault
tolerance, load balancing, resource optimization, energy
management, or adaptive scheduling purposes.

Existing migration approaches range from static failover
mechanisms to fully dynamic runtime migration strategies.
However, implementing migration in real-time systems
introduces several challenges, including state transfer,
synchronization overhead, migration latency, and timing
predictability~\cite{chen2012,megel2010}. The migration
process itself can be decomposed into several phases:
(i)~the \emph{pre-migration} phase, in which the source
node prepares and serializes the task state; (ii)~the
\emph{transfer} phase, during which state data is
transmitted to the destination node over the interconnect;
and (iii)~the \emph{post-migration} phase, in which the
destination node initializes execution from the transferred
state. Each of these phases introduces latency that must
be accounted for in the schedulability analysis of the
migrating task as well as of any tasks that share resources
with it.

Checkpoint-based migration approaches periodically save
a task's execution state to stable storage or shared memory,
enabling resumption from the most recent checkpoint after
a failure or migration event~\cite{elnozahy2002}. While
this reduces the cost of the transfer phase by transmitting
incremental state differences, it introduces regular runtime
overhead for checkpointing and may not be compatible with
hard real-time timing guarantees unless the checkpointing
overhead is explicitly bounded and included in schedulability
analysis.

In heterogeneous distributed systems, migration becomes even
more complex due to architectural differences between hardware
platforms, communication constraints, and execution
environment compatibility. Binary incompatibility between
different instruction set architectures requires either
maintaining multiple compiled variants of each migratable
task, recompilation at migration time, or the use of
intermediate representations or virtual machines that
abstract the underlying hardware. The overhead introduced
by such compatibility layers must be carefully evaluated
against the latency and correctness requirements of the
target application.

\section{Networks and Communication in Real-Time Systems}
\label{sec:networks}

Communication networks represent a critical component of
distributed cyber-physical systems. In real-time systems,
communication mechanisms must provide deterministic behavior,
bounded latency, synchronization support, and fault tolerance.

Traditional automotive systems relied heavily on fieldbus
technologies such as Controller Area Network~(CAN),
FlexRay, and Local Interconnect Network~(LIN). CAN provides
a broadcast, message-priority-based medium access scheme
with well-understood worst-case latency bounds, but its
bandwidth is limited to 1~Mbit/s (or up to 8~Mbit/s with
CAN~FD). FlexRay offers higher bandwidth and a time-triggered
communication model that provides stronger temporal
determinism, but at higher cost and complexity. LIN is used
for low-bandwidth sensor and actuator networks where cost
is paramount. These technologies collectively supported the
domain-oriented ECU architectures of previous vehicle
generations.

% ------------------------------------------------------------
\subsection{Time-Sensitive Networking}
\label{subsec:tsn}

More recent architectures increasingly incorporate
Ethernet-based technologies and Time-Sensitive Networking~(TSN)
mechanisms in order to support higher bandwidth requirements
and improved scalability~\cite{ieee8021q2022}. TSN extends
standard IEEE~802.3 Ethernet with a suite of standards
developed by the IEEE~802.1 working group, collectively
providing mechanisms for traffic prioritization, time
synchronization, bounded latency, and deterministic
communication.

Key TSN standards include IEEE~802.1AS for generalized
precision time protocol~(gPTP)-based clock
synchronization~\cite{ieee8021as2020}, IEEE~802.1Qbv for
time-aware shaping~(TAS), and IEEE~802.1Qbu/802.3br for
frame preemption, which allows high-priority frames to
interrupt the transmission of lower-priority frames. The
Credit-Based Shaper~(CBS) defined in IEEE~802.1Qav provides
bandwidth reservation for audio-video bridging~(AVB) streams.
Together, these mechanisms allow TSN networks to support
multiple traffic classes with heterogeneous latency and
bandwidth requirements on a shared infrastructure.

TSN capabilities are especially relevant for distributed
real-time systems where tasks executing on different nodes
require predictable communication behavior. In the context
of task migration, TSN networks can provide bounded-latency
channels for state transfer, coordination messages, and
monitoring traffic, enabling more predictable migration
latency bounds than best-effort networks. However, the
interaction between TSN traffic scheduling, task scheduling
on computing nodes, and the timing constraints of
distributed applications remains an active area of
research~\cite{craciunas2016}.

% ------------------------------------------------------------
\subsection{Service-Oriented Communication and Middleware}
\label{subsec:middleware}

In addition to transport-layer networking technologies, the
communication middleware used in distributed real-time
systems plays a significant role in system integration and
runtime behavior. The AUTOSAR Adaptive Platform adopts a
service-oriented communication model based on the SOME/IP
protocol~\cite{autosar2023}, which supports dynamic service
discovery and method-call semantics over standard IP
networks. The Data Distribution Service~(DDS) middleware
standard~\cite{omgdds2015} provides a publish-subscribe
communication model with Quality-of-Service~(QoS) policies
governing reliability, latency budgets, deadlines, and
resource limits, and has seen growing adoption in
autonomous and robotic systems through its use as the
underlying transport in the Robot Operating System~2
(ROS2)~\cite{maruyama2016}.

In distributed task migration and orchestration scenarios,
network infrastructure additionally plays an important role
in state transfer, coordination, synchronization, and runtime
monitoring. Communication latency and bandwidth limitations
can significantly influence migration overhead and overall
system schedulability. The co-design of communication
scheduling policies and task scheduling policies for
distributed real-time systems with migration support
constitutes one of the open research problems motivating
the work presented in this dissertation.

\chapter{Related Work and State of the Art}
\label{chap:relatedwork}

The increasing complexity of modern embedded and cyber-physical systems has led to
extensive research on architectures that combine deterministic timing guarantees with
flexibility and runtime adaptability. Classical real-time systems were designed under
static assumptions regarding task sets, execution platforms, and scheduling policies.
However, modern automotive and distributed embedded systems increasingly require
dynamic adaptation to workload variations, heterogeneous hardware, and runtime
reconfiguration. This chapter reviews the most relevant areas of research related to
this dissertation, covering real-time scheduling, mixed-criticality systems, distributed
embedded architectures, task migration, machine learning for scheduling, and prior
work at the chair. Each section concludes by identifying the specific limitations that
motivate the contributions of this dissertation.

% ============================================================
\section{Scheduling and Resource Management in Real-Time Systems}
\label{sec:rw_scheduling}

Foundational work in real-time scheduling established classical models for periodic
task systems and provided schedulability conditions for fixed-priority and
dynamic-priority scheduling algorithms~\cite{liu1973,buttazzo2011}. Rate Monotonic~(RM)
and Earliest Deadline First~(EDF) scheduling remain the primary reference paradigms,
with well-understood optimality properties under their respective assumptions. Response
Time Analysis~(RTA)~\cite{joseph1986} extended these results to account for blocking
and shared resource access under fixed-priority scheduling, providing the analytical
foundation that most industrial real-time system design still relies upon.

As systems have grown more complex, the applicability of uniprocessor scheduling
theory has become increasingly limited. The transition to multicore and heterogeneous
platforms introduces new sources of timing interference that classic models do not
capture: shared cache contention, memory bus saturation, NUMA effects, and
pipeline stalls caused by speculative execution. These phenomena invalidate simple
additive compositional reasoning and have driven a substantial body of research on
memory interference analysis and cache-aware scheduling for multicore
platforms~\cite{mancuso2013,hoornaert2024}.

% ------------------------------------------------------------
\subsection{Multiprocessor and Distributed Scheduling}
\label{subsec:rw_mp_scheduling}

Multiprocessor real-time scheduling introduces additional challenges including task
migration overhead, synchronization costs, and the fundamental complexity of the
multiprocessor feasibility problem. The taxonomy of partitioned, global, and
semi-partitioned scheduling strategies~\cite{davis2011} reflects the trade-off between
analytical tractability and runtime efficiency: partitioned approaches allow
independent per-core analysis but may fail to schedule task sets that global approaches
can handle, while global approaches improve utilization at the cost of migration
overhead and substantially harder schedulability analysis.

Megel et al.\ investigated migration-aware scheduling strategies aimed at minimizing
preemption and migration overhead in global multiprocessor scheduling~\cite{megel2010}.
Their work demonstrates that migration overhead is a first-order concern in practice,
not a secondary effect, and must be explicitly modeled in schedulability analysis.
However, this work addresses shared-memory multiprocessors and does not extend to
distributed heterogeneous systems where migration involves network state transfer.

In distributed systems, scheduling decisions can no longer be considered independently
from the communication infrastructure. End-to-end latency analysis for task chains
spanning multiple nodes~\cite{durr2019} has emerged as a key research area,
particularly in the automotive domain where cause-effect chains connect sensor
acquisition, computation, and actuator output across multiple ECUs. The interaction
between node-local scheduling and network scheduling in TSN-based distributed
systems is an active open problem~\cite{craciunas2016}, with joint optimization
of task and network schedules shown to yield significant improvements over
independent approaches.

\textbf{Gap:} Existing multiprocessor scheduling research addresses migration cost
primarily in shared-memory settings and does not account for criticality
differentiation in migration policy decisions. End-to-end timing analysis for
distributed systems has advanced significantly but has not been extended to
account for the transient scheduling state introduced by runtime task migration.

% ============================================================
\section{Mixed-Criticality Systems}
\label{sec:rw_mcs}

The mixed-criticality model introduced by Vestal~\cite{vestal2007} and subsequently
formalized by Baruah et al.~\cite{baruah2011} has generated a large body of research
over the past fifteen years. The Burns and Davis survey~\cite{burns2017}, now in its
thirteenth edition, documents the breadth of this field and identifies open problems
that remain unresolved. The core mechanism of the standard MC model---mode switching
from LO to HI upon a WCET overrun, with degradation or suspension of low-criticality
tasks---has been extended in multiple directions.

% ------------------------------------------------------------
\subsection{Adaptive and Multicore Mixed-Criticality Scheduling}
\label{subsec:rw_mc_adaptive}

The Adaptive Mixed Criticality~(AMC) scheduler proposed by Burns and
Baruah~\cite{burns2013} introduced per-task mode switching, allowing finer-grained
response to individual task overruns rather than a global system-wide mode change.
This reduces unnecessary degradation of low-criticality tasks when only a subset of
high-criticality tasks approach their pessimistic WCET bounds. Subsequent work
explored elastic and imprecise computation models that allow continuous service
adjustment rather than binary mode transitions, improving utilization while
maintaining safety guarantees.

On multicore platforms, mixed-criticality scheduling must additionally contend with
shared resource interference. Cache partitioning and memory bandwidth
regulation~\cite{mancuso2013} have been identified as essential mechanisms for
providing isolation between criticality levels on shared-cache multicore hardware.
The MCTI framework of Hoornaert et al.~\cite{hoornaert2024} provides a layered
approach to task-based isolation, combining CPU regulation at the OS level with
memory bandwidth control at the hypervisor level, demonstrating that strong isolation
is achievable on commercial off-the-shelf~(COTS) multicore platforms without
specialized hardware.

Flexible and dynamic MC scheduling approaches have also been explored for scenarios
where task criticality is not statically fixed~\cite{jiang2022flexible}. Jiang et
al.\ propose resource allocation mechanisms that dynamically adjust service levels
based on runtime system state, providing a more gradual degradation model than the
binary LO/HI switch. Similarly, energy-aware MC scheduling has received growing
attention, with surveys documenting the trade-off between power consumption and
timing guarantees in battery-constrained embedded systems~\cite{mcsEnergySurvey2022}.

% ------------------------------------------------------------
\subsection{Mixed-Criticality in Distributed and Fault-Tolerant Systems}
\label{subsec:rw_mc_distributed}

Extending MC scheduling to distributed systems introduces the problem of mode
propagation: when a high-criticality task on one node triggers a mode switch, nodes
that share cause-effect chains or communication dependencies with the overrunning
task must also adapt their scheduling behavior. This coordination requires either
synchronous global mode transitions, which introduce communication overhead and
potential blocking, or asynchronous local decisions that may lead to transient
inconsistencies. Neither approach has been fully satisfactorily resolved in the
literature.

Fault-tolerant mixed-criticality scheduling has been investigated by several groups.
The work of Melani et al.~\cite{melani2017} addresses fault-tolerant scheduling of
MC task sets on distributed platforms using temporal redundancy, with spatial
separation constraints derived from hazard analysis. Reghenzani et al.~\cite{reghenzani2022}
propose a mixed-criticality approach to fault tolerance in which criticality levels
directly govern the degree of redundancy and the recovery time budget allocated to
each task. These approaches demonstrate that MC and fault tolerance are complementary
rather than conflicting concerns, but they assume static task allocation and do not
address the case where the execution node of a task changes at runtime.

The most directly relevant recent work to this dissertation is that of Baik et
al.~\cite{baik2022}, who propose a task migration and scheduling framework
specifically for mixed-criticality systems in vehicle safety applications. Their
approach allows low-criticality tasks to temporarily execute on neighboring nodes
when their local platform is under high load, effectively extending schedulability
by borrowing compute capacity, while preserving high-criticality task guarantees
through deadline-based compatibility tests. However, their approach operates at the
task activation level rather than providing a full execution state migration
mechanism, and does not address the state transfer, checkpoint, and loading
overhead involved in migrating a partially-executed task.

\textbf{Gap:} The intersection of MC scheduling with runtime execution state
migration, where a task's in-progress execution, including stack state and
accumulated progress, is transferred to a different node, has not been addressed.
Existing distributed MC work either assumes static allocation or addresses only
coarse-grained failover at the task activation level.

% ============================================================
\section{Distributed Real-Time Systems and Automotive Architectures}
\label{sec:rw_distributed}

Distributed real-time systems consist of multiple computational nodes connected via
a communication network, and are the dominant architecture in automotive, aerospace,
and industrial automation domains. The automotive domain has undergone particularly
rapid architectural evolution in recent years, driven by the growing computational
demands of ADAS, autonomous driving, and software-defined vehicle~(SDV) functionality.

% ------------------------------------------------------------
\subsection{Automotive Architecture Evolution}
\label{subsec:rw_automotive}

The traditional domain-oriented ECU architecture, in which separate ECUs independently
manage powertrain, chassis, body electronics, and infotainment, is giving way to
centralized and zonal architectures~\cite{sdv2024,automotivehpc2023}. In a zonal
architecture, ECUs are grouped by physical vehicle zone rather than by function,
with high-bandwidth Ethernet backbones connecting zone controllers to one or more
central compute platforms. This consolidation reduces wiring harness complexity, a
significant factor in vehicle weight and assembly cost, while enabling more powerful
centralized processing and simpler over-the-air software updates.

The SDV concept extends this further by treating all vehicle functions as software
services deployable and updatable independently of the underlying hardware. Industry
adoption is accelerating: major OEMs and Tier-1 suppliers have announced centralized
compute platform programs, and the AUTOSAR Adaptive Platform~\cite{autosar2023}
provides a standardized software framework targeting these high-performance computing
nodes with support for dynamic service deployment and POSIX-compatible execution
environments.

From a research perspective, this architectural transition surfaces a critical
challenge: as more functions are consolidated onto fewer, more powerful nodes, the
consequences of a node failure become more severe, making fault tolerance and runtime
adaptation---including task migration---correspondingly more important.

% ------------------------------------------------------------
\subsection{Time-Sensitive Networking}
\label{subsec:rw_tsn}

Time-Sensitive Networking~(TSN) has emerged as the dominant communication technology
for deterministic Ethernet-based distributed embedded systems. The suite of IEEE 802.1
amendments provides mechanisms for time synchronization~(802.1AS), time-aware traffic
shaping~(802.1Qbv), frame preemption~(802.1Qbu), and credit-based
shaping~(802.1Qav), collectively enabling multiple traffic classes with heterogeneous
latency and bandwidth requirements to coexist on shared infrastructure.

The scheduling of time-triggered traffic in TSN networks using the Time-Aware
Shaper~(TAS) has attracted substantial research attention. St\"{u}ber et
al.~\cite{stuber2022} provide a comprehensive survey of TAS scheduling algorithms,
documenting the optimization objectives, problem formulations, and evaluation
methodologies of existing approaches. A more recent systematic review and experimental
study by Xue et al.~\cite{xue2024} evaluates 17 representative TAS scheduling methods
on both simulation and real hardware testbeds, identifying that no single method
dominates across all scenarios and that the interaction between network topology,
traffic pattern, and scheduling algorithm is highly application-specific.

Joint scheduling of tasks and network traffic in TSN-based distributed real-time
systems has been shown to offer significant improvements over independent
approaches~\cite{craciunas2016}. In such systems, the network schedule and the task
schedule on each node are mutually dependent: the timing of task activations
determines when frames are generated, while the network schedule determines when
results become available for downstream tasks. This co-design problem becomes even
more complex when tasks may migrate between nodes at runtime.

\textbf{Gap:} Existing TSN scheduling research does not address the case where the
task assignment to nodes changes dynamically. Migration introduces transient traffic
patterns (e.g. state transfer streams, coordination messages) that are not captured in
any existing TSN scheduling model, and may require dynamic reconfiguration of the
network schedule during a migration event.

% ============================================================
\section{Task Offloading and Orchestration in IoT and Edge Systems}
\label{sec:rw_edge}

In parallel to research on distributed real-time systems, a large body of work in the
Internet of Things~(IoT), edge computing, and fog computing has investigated the
problem of task offloading and resource orchestration across heterogeneous computing
nodes. These works provide relevant conceptual models and optimization techniques,
even though their primary target is best-effort or soft real-time workloads.

Mao et al.~\cite{mao2017mobile} studied computation offloading strategies in mobile
edge computing~(MEC) systems, demonstrating that optimal offloading decisions must
jointly account for communication cost, computation latency, and energy consumption,
and that these factors interact in non-trivial ways depending on dynamic system
conditions. You et al.~\cite{you2017energy} extended this to joint communication and
computation resource allocation, showing that network and compute constraints must
be optimized simultaneously rather than independently.

Container-based virtualization has been increasingly adopted for edge computing
deployments, offering process isolation and portability with lower overhead than
full virtual machines. Empirical studies of checkpoint/restore in containerized
environments~\cite{tosic2023} demonstrate that container migration latency is
dominated by the size of the process memory image and network transfer time rather
than by container initialization overhead, a finding that directly informs the
Virtual ECU migration strategy investigated in this dissertation. Morabito et
al.~\cite{morabito2018} evaluated the performance overhead of container
virtualization on IoT edge devices, finding that containerization imposes measurable
but manageable overhead for compute-bound workloads while adding significant latency
for storage and network operations.

A fundamental limitation of IoT and edge offloading research is its assumption of
relaxed or best-effort timing constraints. Offloading frameworks prioritize
throughput, energy efficiency, or cost, and treat latency as a soft optimization
objective rather than a hard real-time requirement. This limits the direct
applicability of these approaches to safety-critical embedded systems. Nevertheless,
the architectural patterns for dynamic task placement, hierarchical resource
management, and state transfer developed in this body of work provide valuable
reference models for the Virtual ECU migration tier explored in this dissertation,
where non-safety-critical tasks may be offloaded to edge resources under controlled
conditions.

\textbf{Gap:} Edge and IoT offloading frameworks do not provide hard real-time
guarantees and do not integrate with onboard mixed-criticality scheduling. The
conditions under which edge offloading is safe for tasks at the lowest criticality
levels of an automotive MC system---and the latency and reliability constraints that
the communication path must satisfy---have not been systematically studied.

\section{Task Migration in Real-Time Systems}
\label{sec:rw_migration}

Task migration has been studied from several angles in the real-time systems
literature: as a mechanism for load balancing in multiprocessor scheduling, as a
fault recovery mechanism in distributed systems, and more recently as a component
of adaptive orchestration frameworks.

% ------------------------------------------------------------
\subsection{Migration Overhead and Schedulability}
\label{subsec:rw_migration_overhead}

In multiprocessor real-time scheduling, migration overhead is a well-recognized
first-order concern. Megel et al.~\cite{megel2010} demonstrated that migration
and preemption costs must be explicitly bounded and included in schedulability
analysis, and proposed scheduling strategies that minimize the number of migrations
while preserving global feasibility. Their work established that the commonly used
simplification of treating migration as instantaneous is untenable in practice.

More recent work on migration-aware scheduling in heterogeneous multiprocessor
systems~\cite{davis2011} has confirmed that the overhead of migration---including
cache repopulation, TLB invalidation, and pipeline refilling on the destination
processor---can dominate the actual task execution time for short-period tasks,
making migration frequency a critical design parameter.

% ------------------------------------------------------------
\subsection{Fault-Tolerant Migration in Embedded Systems}
\label{subsec:rw_migration_fault}

In fault-tolerant embedded systems, migration is primarily used as a recovery
mechanism triggered by hardware failure. Chen and Lyu~\cite{chen2012} proposed a
FlexRay-based framework in which backup ECUs take over execution when the primary
fails. However, their approach operates at coarse granularity: entire ECU function
groups are reassigned, rather than providing fine-grained task-level migration with
state preservation. The checkpoint-restore approach to fault-tolerant migration,
surveyed comprehensively by Elnozahy et al.~\cite{elnozahy2002}, provides a
principled mechanism for capturing and restoring execution state, but the original
work targets message-passing cluster systems rather than resource-constrained
embedded nodes with hard real-time constraints.

Checkpoint-based migration in real-time embedded contexts introduces the specific
challenge that the checkpointing operation itself consumes time and memory resources,
and this overhead must be budgeted in the schedulability analysis of the checkpointed
task. If checkpointing is performed periodically, the checkpoint interval must be
chosen to balance recovery cost (coarser intervals mean more re-execution after
recovery) against runtime overhead (finer intervals impose more frequent interruptions).

% ------------------------------------------------------------
\subsection{Runtime Migration in Distributed Real-Time Systems}
\label{subsec:rw_migration_distributed}

Research on runtime task migration specifically for distributed real-time systems
remains limited. The DFT4FTT project investigated adaptive task allocation in
distributed embedded systems supporting real-time, reliability, and adaptivity
requirements, proposing greedy online heuristics for migrating safety-critical tasks
in response to permanent faults while adjusting soft real-time task service parameters
on the target node~\cite{dft4ftt}. This work represents one of the closest precedents
to the approach developed in this dissertation, but does not address mixed-criticality
scheduling or the ELF-based execution state transfer mechanisms required for
heterogeneous embedded targets.

The interaction between dynamic task migration and TSN network scheduling has been
highlighted as an open problem by recent work on joint task and network
scheduling~\cite{craciunas2016,xue2024}: a migration event changes the traffic
pattern on the network, potentially invalidating the network schedule that was
computed for the static task assignment.

\textbf{Gap:} No existing work provides a complete runtime task migration system for
distributed embedded real-time systems that (a)~differentiates migration policy and
mechanism by criticality level, (b)~handles the full execution state transfer
including checkpoint and ELF-based loading on heterogeneous embedded targets,
and (c)~accounts for the schedulability implications of migration events on both
source and destination nodes under a mixed-criticality scheduling framework.

\section{Machine Learning for Scheduling and Deployment}
\label{sec:rw_ml}

Machine learning techniques have been increasingly applied to scheduling and resource
allocation problems due to their ability to approximate complex optimization objectives
that are intractable for exact methods. In the real-time scheduling domain, the
primary motivation is the computational cost of exact schedulability analysis for
large task sets: algorithms such as response time analysis scale poorly with the
number of tasks and become infeasible for runtime use.

Early work explored neural network approaches for offline schedulability prediction
and task ordering~\cite{cardeira1994,dominguez2004}. These approaches demonstrated
that learned predictors could achieve high accuracy on synthetic task sets, but were
limited to offline design-time use and did not generalize well across task set
distributions.

More recent research at the chair, conducted across multiple theses~\cite{taieb1,
	utz1,blieninger1}, applied neural network-based feasibility prediction to the
migration planning problem. The key insight is that predicting schedulability, a
binary decision, is faster than computing exact response times, making runtime
replanning tractable even for large task sets. The trade-off is that neural network
predictions are not unconditionally safe: false positive predictions~(declaring a
task set feasible when it is not) can occur, and the rate of such errors must be
characterized and bounded for safety-critical use.

Reinforcement learning~(RL) has been applied to dynamic scheduling and routing
problems in TSN and edge environments, with promising results in simulation but
limited deployment in safety-critical real-time systems. The fundamental challenge
is that RL policies do not provide formal timing guarantees: a learned policy may
perform well on average but cannot be certified to satisfy hard deadlines under all
possible inputs. Bridging the gap between the performance of ML-based approaches
and the certification requirements of safety-critical domains remains an open
research problem.

\textbf{Gap:} Existing ML-based scheduling and planning tools at the chair were
developed for single-criticality task sets and do not incorporate mixed-criticality
parameters. Extending one of these tools to support MC task sets, where each task has
multiple WCET estimates and the feasibility prediction must account for potential
mode switches, is a secondary contribution of this dissertation.

\section{Prior Work at the Chair}
\label{sec:rw_chair}

Research at the Chair of Operating Systems at TUM has produced a series of projects
and theses directly relevant to this dissertation. These works form the technical
and conceptual foundation for task migration and adaptive execution in distributed
embedded systems. However, their focus differs fundamentally from the approach
presented in this dissertation: prior work primarily investigates migration as a
planning, orchestration, or checkpointing problem, while assuming that a runtime
execution substrate for stateful task migration is either available or abstracted
away.

The KIA4SM project~\cite{eckl2015} introduced a cooperative integration architecture
for smart mobility systems based on Genode OS and Fiasco.OC. It demonstrated the
feasibility of distributed automotive software components and introduced a
two-stage migration concept (planning and execution). However, the execution stage
relies on system-level abstractions and does not provide a lightweight mechanism
for directly transferring and resuming task execution state on heterogeneous
embedded targets.

The HaCRoM project extended checkpoint-restore mechanisms for fault-tolerant task
migration in real-time systems. While this work established important empirical
insights into checkpoint overhead and feasibility, it primarily focuses on state
capture and recovery as a fault tolerance mechanism. The actual execution of
migrated tasks is still assumed to be supported by the underlying runtime system,
rather than being implemented as a minimal operating-system-level capability.

The MaLSAMi project shifted focus toward migration decision-making and planning
using machine learning-based schedulability prediction. A series of theses by
Taieb~\cite{taieb1}, Utz~\cite{utz1}, and Blieninger~\cite{blieninger1} improved
the accuracy of feasibility prediction models for task allocation and migration
decisions. However, these approaches operate at the level of decision support and
do not address how a task is actually executed after migration, particularly in
heterogeneous embedded environments.

A parallel line of work by Delgadillo~\cite{delgadillo1} transitioned parts of the
execution environment to FreeRTOS, enabling experiments closer to embedded hardware
constraints. Nevertheless, the system still assumes that task execution is locally
bound and does not provide a mechanism for transferring partially executed runtime
state between nodes with different execution contexts.

In summary, prior work at the chair has progressively addressed migration planning,
checkpointing, and feasibility prediction, but none of these systems implement
migration as a first-class execution primitive within a lightweight embedded
operating system. Instead, migration is treated as a higher-level orchestration
decision, while the execution of migrated tasks remains outside the scope of the
runtime system itself.

None of the prior projects at the chair integrate mixed-criticality concepts into
a complete runtime migration execution system. More importantly, none provide a
lightweight OS-level mechanism for stateful task migration across heterogeneous
embedded nodes.

The contributions of this dissertation address this gap by introducing Axcan OS,
a FreeRTOS-based execution substrate that enables stateful task migration as a
first-class primitive, including execution state capture, transfer, and resumption
on heterogeneous embedded platforms. This runtime capability forms the foundation
on which higher-level scheduling, mixed-criticality management, and planning
mechanisms operate.

\section{Research Gap Summary}
\label{sec:rw_gap}

The reviewed literature demonstrates substantial progress across real-time scheduling theory,
mixed-criticality systems, distributed embedded architectures, communication networks, and
task migration research. Classical real-time scheduling provides a strong analytical basis
for fixed and dynamic priority systems under static task assumptions. Mixed-criticality
research extends these models with adaptive execution modes and controlled degradation
strategies. Distributed real-time systems and Time-Sensitive Networking (TSN) provide
deterministic communication foundations for networked embedded systems. Finally, task
migration and checkpointing techniques explore mechanisms for relocating computation,
primarily in the context of fault tolerance or load balancing.

Despite these advances, existing approaches share a fundamental architectural limitation:
\textit{task execution is assumed to be bound to a fixed runtime execution context, and
	migration is treated as either a high-level scheduling decision or a coarse-grained fault
	recovery action, rather than as a continuous, OS-supported execution capability}. In all
existing models, the operating system is assumed to execute tasks locally, while migration
is abstracted as task reactivation, restart, or external orchestration.

This abstraction leads to a missing execution layer in current distributed embedded systems:
there is no lightweight operating system substrate that enables \textbf{stateful, partially
	executed task migration across heterogeneous nodes as a first-class runtime primitive}.
As a result, several fundamental limitations remain unresolved:

\begin{enumerate}
	
	\item \textbf{Absence of OS-level execution state migration mechanisms.}  
	Existing checkpoint-restore and migration approaches operate as external mechanisms or
	framework-level services. They do not integrate execution state capture, transfer, and
	resumption directly into a lightweight real-time operating system. Consequently, partially
	executed tasks cannot be transparently migrated and resumed across heterogeneous embedded
	nodes with minimal runtime overhead.
	
	\item \textbf{Static execution binding in distributed real-time systems.}  
	Current distributed scheduling models assume a fixed mapping between tasks and execution
	nodes. Migration, when considered, is modeled as a discrete reassignment event rather than
	a runtime continuation of execution state. This prevents accurate modeling of transient
	execution phases, where a task is simultaneously influenced by source-side execution state,
	transfer latency, and destination-side scheduling constraints.
	
	\item \textbf{Incompatibility of migration with deterministic communication schedules.}  
	TSN-based systems assume statically known traffic patterns derived from fixed task-to-node
	assignments. Stateful task migration violates this assumption by introducing dynamic,
	time-varying communication flows, including execution state transfer and coordination traffic,
	which are not represented in existing offline-computed network schedules.
	
	\item \textbf{Lack of real-time capable offloading with execution continuity.}  
	Edge and IoT offloading frameworks support dynamic task placement across heterogeneous
	resources, but treat tasks as restartable computation units. They do not provide mechanisms
	for preserving execution continuity under hard real-time constraints, nor do they integrate
	with embedded operating system scheduling semantics.
	
	\item \textbf{Separation of learning-based decision models from execution mechanisms.}  
	Machine learning approaches for scheduling and migration focus on predicting feasibility or
	optimizing allocation decisions, but assume that execution after migration is handled by an
	external runtime system. They do not model or control the execution state transfer process,
	nor its impact on real-time schedulability in mixed-criticality systems.
	
\end{enumerate}

\noindent
These limitations converge to a single fundamental gap: \textbf{the absence of a lightweight
	operating system execution substrate that enables stateful task migration as a first-class
	primitive in distributed heterogeneous real-time systems, while preserving real-time
	constraints during execution state transfer and resumption.}

This dissertation addresses this gap through the design and implementation of Axcan OS, a
FreeRTOS-based execution substrate that integrates execution state capture, transfer, and
resumption directly into the runtime system. On top of this substrate, higher-level
mechanisms for scheduling, mixed-criticality management, and migration planning can operate
without assuming static task-to-node bindings, enabling a new class of adaptive distributed
real-time systems.
